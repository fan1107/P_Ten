# THE TEN! — prototype / score & combo update 2026-11-01

## 실행

Unity 6000.3.23f1에서 `Assets/Scenes/TheTen.unity`를 열고 Play를 누른다.
홈의 LET'S PLAY로 시작한다. 마우스 클릭과 모바일 터치가 동일한 UGUI 버튼을 사용한다.
세로 720×1280 기준 UI는 Screen.safeArea 안에 비율을 유지한다.
`Assets/TheTen/GameBalance.asset`에서 시간, 확률, 최대 층수, 셔플 탐색 예산과 Mock 정책을 조정한다.
기존 SampleScene은 보존했다. Build Settings 시작 씬은 TheTen이다.

## 구현된 규칙

- 30장 적층 + 6장 자유 패, 총 36장. 1챕터는 15/9/6장의 세 단을 엇갈려 쌓는다.
  화면 좌표의 사각형 겹침으로 윗패를 판정하며, 겹치는 윗패가 모두 제거되어야 선택 가능하다.
  그림과 판정은 동일한 X/Y 및 크기를 사용한다. 높은 챕터에서도 총 30장과 층별 3의 배수를 유지한다.
- 세 번째 터치에만 계산. 재터치 취소, 가려진 패 무시, 실패 페널티 없음.
- 0, −1, 순서에 따른 ×2, ×2 첫 선택/중복 사용 금지.
- 성공 조합 1회마다 기본 10점과 +8초. 시작 40초, 부활 30초, 최대 부활 1회.
- 이전 성공 후 3초 미만에 다시 성공하면 ×1.5 → ×2 → ×2.5 → ×3 → ×4 → ×5까지 증가하고 유지한다.
  첫 성공은 ×1이며 각 성공 시 3초를 갱신한다. 점수는 10, 15, 20, 25, 30, 40, 50, 50…점이다.
  3초가 소진되면 초기화한다. 실패 조합은 점수/시간 갱신 없이 기존 콤보 창만 유지한다.
  일시정지/보드 전환/셔플은 콤보 시간도 정지한다. 사망은 콤보를 초기화하지만 누적 점수는 유지한다.
  시간바 바로 아래의 가로 콤보 바에 잔여시간과 배율을 표시한다.
  성공 시 획득 점수/배율 팝업이 확대 후 위로 떠오르며 약 1.15초 안에 사라진다.
  높은 배율일수록 확대 폭이 커지고, 5배에서는 MAX COMBO를 표시한다.
  콤보 바와 팝업 강조색은 노랑 → 주황 → 빨강 → 분홍 → 보라로 바뀐다.
  팝업은 입력을 차단하지 않으며 빠른 연속 성공은 하나의 팝업을 갱신한다.
- 36장 제거 시 보드를 교체한다. 챕터는 누적 제거량 / 36으로 독립 계산한다. 점수와 진행 중인 콤보는 유지한다.
- 실제 생존한 시간만 합산. 사망 프레임 초과분, 메뉴, 광고, 선택 대기, 전환, 셔플, 백그라운드 시간 제외.
- 자동 셔플은 남은 값 재배치를 먼저 시도하고 BoardSolver가 전체 해결 경로를 확인한다.
- 일반 생성도 전체 해결 경로를 구성하고 검증한다. 확률은 유효 조합 조건부 표본으로 보정되므로 원래 목표 가중치와 실측 비율은 달라진다.
- 순수 숫자/게임 모델과 UI, 광고, 구매, 저장 구현을 분리했다.

## 셔플 복구의 경계

유한한 재배치/탐색으로 해를 찾지 못하면 남은 패의 값만 다시 생성한다. 위치, 층, 제거 상태는 유지한다.
이때 전체 해결 경로를 구성하며 셔플 보너스는 한 번만 지급한다.
사용자가 패를 제거한 결과 선택 가능한 패가 3장 미만으로 남는 등 고정 적층 구조 자체가 불가능해지면,
구조를 바꾸거나 공짜 제거를 하지 않고 해당 판을 안전하게 종료한다. 이것은 프로토타입 복구 정책이다.
무한 재시도, 멈춤, 반복 보너스를 방지하지만 출시용 복구 UX/정책은 추가 확정이 필요하다.
GameBalance.BoardRecovery에서 값 재생성 허용 여부를 선택할 수 있다.

## 부활권

ReviveTicketManager는 HasAdFreeRevivePurchase, CurrentTicketCount, LastResetDate를 저장한다.
DailyTicketAmount=2, MaxTicketCount=2, ResetTimezone=Asia/Seoul.
서버가 확인한 날짜가 증가했을 때만 2장으로 덮어쓴다. 이월/누적 없음.
동일 날짜 복원/재실행/재요청에 재지급하지 않는다. 과거 서버 날짜 응답은 거부한다.
시각 조회 실패 또는 저장 실패는 RecheckRequired로 처리하며 소비/지급을 보류한다.
동시 호출은 직렬화하고 같은 실행 ID에 대한 연속 중복 차감을 거부한다.
최초 접속, 앱 복귀, 30초 주기, 구매/복원 및 소비 직전에 서버 시각을 재확인한다.
소비 저장을 성공시킨 후에만 UI가 부활을 실행한다. 단말기 DateTime.Now/UtcNow를 사용하지 않는다.

## Mock과 실제 연동의 구분

이 버전은 명세의 “실제 계정이 필요한 기능은 Mock을 먼저 구현” 원칙에 따른 프로토타입이다.
실제 광고 SDK, 스토어 SDK, 영수증 검증 서버, 인증/서버 저장소는 아직 연결되지 않았다.
Mock 상태는 UI에 명시하며 실제 결제는 일어나지 않는다. 표시된 9,000원은 명세의 참고 가격이다.

- MockServerClock: 독립적인 고정 테스트 시각(2026-10-31 23:59 KST) + 단조 증가 경과시간.
  실제 신뢰 서버가 아니다. 재실행 시 테스트 시각은 원점으로 돌아간다.
  LAB의 +1 DAY로 전날 잔액 초기화를, ONLINE/OFFLINE으로 재확인 보류를 시험한다.
  저장된 초기화 날짜가 이 테스트 시각보다 미래이면 정상적으로 지급을 보류한다.
- MockPurchaseGateway: 별도 PlayerPrefs 키로 비소모성 상품의 Mock 소유권을 보관한다.
  구매와 복원 모두 검증 결과 인터페이스를 거쳐 지급한다.
- MockRewardedAdService: 완료/취소/로드 실패를 LAB에서 선택한다. 완료에만 부활한다.
- EnableMockCommerce=false: 외부 서비스 미연결 상태로 명시적으로 실패한다. 기기 시각으로 대신 지급하지 않는다.
- LocalRanking: 기기 내 최고 점수를 저장한다. 글로벌 랭킹 서버는 아니다.
  점수 키는 `.Prototype.BestScore.v1`이며 과거 `.Prototype.BestSeconds`는 점수로 변환하거나 읽지 않는다.

출시 전에 ITrustedServerClock / IPurchaseGateway / IRewardedAdService를 실제 어댑터로 교체해야 한다.
IPurchaseGateway는 계정에 연결된 서버에서 스토어 영수증, 상품 ID, 환불/취소 상태를 검증해야 한다.
서버 시각은 인증된 HTTPS 백엔드에서 신선도를 확인한 응답이어야 한다.
PlayerPrefs는 프로토타입 저장이며 변조 방지 수단이 아니다. 실제 운영에서는 일일 초기화/잔액/소비를
서버의 원자적 트랜잭션과 runId 멱등 키로 처리해야 재설치, 여러 기기, 응답 유실까지 안전하다.
Android/iOS 빌드 및 스토어 샌드박스 검증은 아직 수행하지 않았다.

## 아직 확정되지 않은 항목

MaxRemainingTime=90, BoardClearBonus=0은 임시값이다. 광고 로드 실패 시 기본 정책은 부활 선택 화면 유지다.
파일로 전달된 v3.0 원문은 10.4의 “구매 상태 저장”에서 끝난다.
별도의 스킨 상품 명세/가격, 글로벌 랭킹 규약, 후반부 명세는 제공되지 않아 임의 확정하지 않았다.
