# R&D: 36장 전체 적층 보드

상태: 36장 전체 적층 적용 중. 2026-11-02 현재 코드·설정과 변경 전 백업을 대조했다.
`before/`는 실험 직전 기록이며 현재 사양 문서가 아니다. 현재 코드에서 자유 패 버전으로 돌아가려면
아래 호환성 안내를 확인하고 필요한 변경만 선택적으로 반영해야 한다.

## 비교

| 항목 | 실험 전 백업 | 현재 구현 |
|---|---|---|
| 적층/자유 패 | 30 + 6 | 36 + 0 |
| 첫 챕터 층 구성 | 15 / 9 / 6 | 18 / 12 / 6 |
| 패 크기 (720×1280 기준) | 92×116 | 108×136 |
| 보드 영역 높이 | 440 | 626 |
| 하단 자유 패 트레이 | 있음 | 없음 |
| 콤보 팝업 | 보드 하단 부근 | 콤보 슬라이더 중앙 (720×1280 기준 X=360, Y=309) |

현재 `Assets/TheTen/GameBalance.asset`와 `GameBalance.cs`의 기본값은 시작 30초, 성공 +3초, 셔플 +8초,
부활 30초, 최대 남은 시간 90초, 챕터 클리어 추가 시간 0초다. 이전 문서의 시작 40초·성공 +8초는 현재 설정이 아니다.
실패 조합은 `MissPenalty=3`에 따라 -3초와 전체 선택 해제를 적용한다. 패 재클릭 취소와 빈 공간 전체 취소에는 페널티가 없다.
기본 점수는 10점이며 3초 콤보는 최대 ×5, 특수 패 점수 보너스는 0/−1에 ×2, ×2 패에 ×4다.
현재 챕터는 누적 제거량이 아니라 해당 보드의 모든 패 제거 후 CLEAR 팝업에서 CONFIRM을 눌러 새 보드를 생성할 때 증가한다.
기준 코드는 `BoardModel.cs`, `RunModel.cs`, `TheTenApp.cs`, `ComboFeedback.cs`다.
자유 패가 사라져 선택 가능한 숫자가 달라지므로 체감 난이도와 셔플 빈도를 플레이로 비교해야 한다.
생성 보드는 전체 해결 경로를 구성하며 EditMode 테스트에서 경로를 검사한다. 임의의 모든 플레이 순서가 끝까지 풀리는 것은 보장하지 않는다.
현재 셔플 복구는 숫자 재배치를 먼저 시도하고, 적층 구조 자체가 막힌 경우 남은 패의 위치와 층도 재정렬한다.

## 백업 / 롤백

`before/`에 이번 변경 대상 8개 파일과 해당 Unity .meta를 원래 경로대로 보관했다.
`baseline-manifest.json`은 실험 직전에 기록한 SHA-256 목록이다.
게임 설정 asset, 씬, 아트 리소스는 이 백업과 복구 목록에 포함되지 않는다.
`Assets` 밖의 백업이므로 Unity에서 백업 C# 파일을 중복 컴파일하지 않는다.

`RestoreBaseline.ps1`을 인자 없이 실행하면 해시 검증을 시도하고, 모두 일치할 때 복구 대상만 보여준다.
실제로 복구할 때만 `-Apply`를 붙인다. 적용 전 현재 파일도 `pre-restore-<id>/`에 보관한다.
적용할 때는 Unity Play를 중지해야 한다. 스크립트는 Play 상태를 자동 검사하지 않는다.
기존 아트/결제 데이터 및 다른 파일은 삭제하지 않는다. 적용 후 Unity Refresh, 컴파일 확인과 테스트가 필요하다.

2026-11-02 미리보기 실행은 `BoardModel.cs`의 `Snapshot hash mismatch`로 중단되었다.
현재 백업 8개 모두 저장된 바이트 기준 해시가 목록과 다르다. 파일을 변경하지 않고 메모리에서 CRLF를 LF로 정규화하면
6개는 일치하지만, `TheTenTests.cs`와 `PrototypeFlowTests.cs`는 줄바꿈 정규화 후에도 일치하지 않는다.
따라서 복구 전에 백업 원본과 해시 차이를 확인해야 하며, 현재 상태에서 검증을 건너뛰거나 목록만 다시 생성해서 적용하면 안 된다.

현재 체크아웃에는 백업 이후 추가된 `Assets/TheTen/Runtime/HomeMenu.cs`가 있으며 `partial class TheTenApp`을 선언한다.
백업의 `TheTenApp.cs`는 `partial`이 없는 클래스이므로 그대로 덮어쓰면 현재 HomeMenu와 함께 컴파일할 수 없다.
또한 `RunModel.cs`와 `GameBalance.asset` 등은 복구 대상에 없어 이 스크립트만으로 당시 프로젝트 전체가 복원되지 않는다.
백업 이후 같은 파일에 추가된 홈·랭킹·특수 패·챕터 전환 변경과 문서도 덮어쓰므로, 현재 버전에서는 diff를 검토해 필요한 변경만 선택적으로 복구한다.
`before/`의 문서와 `baseline-manifest.json`은 당시 내용과 해시 검증을 보존하기 위해 현재 사양으로 갱신하지 않는다.
